# Security policy

## Reporting a vulnerability

Use the repository's private GitHub Security Advisory reporting flow when it is
enabled. If private reporting is unavailable, open only a non-sensitive issue
asking the maintainers for a private contact channel. Do not place vulnerability
details or secrets in that issue. Never open a public issue containing
authentication files, tokens, decrypted profile data, account email addresses,
logs with authorization headers, or screenshots that expose credentials.

Include the affected version, Windows version, provider, reproduction steps
using synthetic credential files, and the expected security property. Remove
all real account data before attaching diagnostics.

## Supported scope

Security fixes target the current `main` branch and the newest rolling release.
This project does not claim to protect secrets from malware running under the
same Windows user. Its vault is intended to prevent accidental plaintext
storage and cross-user access, not to replace endpoint security.

## Credential-handling requirements

- Never parse, decode, normalize, or log a provider authentication file.
- Keep credential data in byte buffers and clear buffers after use when
  practical.
- Encrypt saved snapshots with Windows DPAPI `CurrentUser` scope.
- Never place plaintext backup files in the vault or repository.
- Block capture and switching when a related process is running or process
  state cannot be checked reliably.
- Write replacement files in the destination directory, flush them, and use an
  atomic replacement operation with recovery state.
- Derive plaintext replacement temporary and backup filenames from the
  non-secret journal transaction ID. Delete only those exact owned files during
  commit, rollback, or recovery, and delete the journal last.
- Preserve pre-restore live bytes only in a transaction-specific DPAPI-encrypted
  recovery blob. Keep it until the journal is deleted successfully, then remove
  it on a best-effort basis so a journal is never stranded without rollback data.
- Treat a live authentication file that differs from the last selected snapshot
  as ambiguous until the user explicitly confirms the exact observed bytes.
  Never reuse that confirmation for different live authentication contents.
- Tests must use generated bytes in temporary directories only.
