# Coding Agent Account Switcher

[English](README.md) · [简体中文](README.zh-CN.md) · [繁體中文](README.zh-TW.md) · [Español](README.es.md) · [Français](README.fr.md) · [Deutsch](README.de.md) · [日本語](README.ja.md) · [한국어](README.ko.md) · [Português (Brasil)](README.pt-BR.md) · [Русский](README.ru.md) · [العربية](README.ar.md) · [हिन्दी](README.hi.md)

أداة Windows غير رسمية ومحلية أولاً لتبديل الحسابات ومواقع API في Codex وClaude Code وOpenCode.

يحفظ Coding Agent Account Switcher لقطات مشفرة لبيانات الاعتماد المحلية مع حقول مزود API الضرورية فقط. تبقى بقية الإعدادات وMCP والمهارات والمكونات الإضافية وسجل المشاريع في مواقعها الأصلية.

> [!IMPORTANT]
> هذا المشروع غير تابع لـ OpenAI أو Anthropic ولم يحظَ بتأييدهما أو رعايتهما. لا ينقل الاشتراكات، ولا يتجاوز متطلبات تسجيل الدخول، ولا يشارك الحسابات، ولا يتحايل على سياسات مزود الخدمة أو المؤسسة.

يشير وصف «مستوحى من iOS 18» إلى التوجه البصري العام فقط. لا ترتبط Apple بهذا المشروع، ولا يتضمن أي خطوط أو رموز أو أعمال فنية أو علامات تجارية خاصة بها.

## التنزيل

نزّل البناء الحالي من [إصدار latest](https://github.com/zzz1999/coding-agent-account-switcher/releases/latest):

- **المثبّت الموصى به:** يثبّت `coding-agent-account-switcher-setup-win-x64.exe` التطبيق للمستخدم الحالي في Windows من دون صلاحيات المسؤول، وينشئ إدخالين في قائمة ابدأ ولإلغاء التثبيت.
- **الملف التنفيذي المحمول:** نزّل `coding-agent-account-switcher-portable-win-x64.exe` وشغّله مباشرةً من دون تثبيت.
- يتضمن الإصدار ملف مجموع تحقق SHA-256 مطابقاً لكل ملف تنفيذي.

لا يفعّل المثبّت خيار **البدء مع Windows** تلقائياً، ولا يلمس ملفات مصادقة أو إعدادات Codex أو Claude Code أو OpenCode. يحتفظ إلغاء التثبيت بلقطات الحسابات المشفرة وإعدادات التطبيق لتظل متاحة بعد إعادة التثبيت. المثبّت والملف التنفيذي المحمول غير موقّعين حالياً، لذلك قد يعرض Windows SmartScreen تحذيراً متعلقاً بالسمعة.

## الميزات

- واجهة WPF أصلية لنظام Windows بتصميم بطاقات زجاجية مستوحى من iOS 18.
- لغات واجهة مدمجة: الإنجليزية، والصينية المبسطة والتقليدية، والإسبانية، والفرنسية، والألمانية، واليابانية، والكورية، والبرتغالية البرازيلية، والروسية، والعربية، والهندية.
- إعدادات داخل التطبيق لاختيار لغة العرض والتشغيل الاختياري مع Windows للمستخدم الحالي.
- ملفات تعريف شخصية وللعمل ولمواقع API بأسماء مخصصة لكل من Codex وClaude Code وOpenCode.
- حارس للعمليات يمنع التبديل إلى أن تُغلق التطبيقات ذات الصلة.
- تبقى ملفات المصادقة بايتات مبهمة؛ ولا تُحلل وتُدمج إلا الحقول المُدارة أدناه، ولا تُعرض الأسرار أو تُسجل أبداً.
- تشفير لقطات ملفات التعريف باستخدام Windows DPAPI للمستخدم الحالي في Windows.
- استبدال ذري للملفات المُدارة داخل المجلد نفسه مع دعم التراجع.
- تأكيد صريح قبل أن تتمكن جلسة دخول نشطة متغيرة من الكتابة فوق لقطة آخر ملف تعريف محدد.
- إجراء آمن **استعادة اللقطة** لآخر ملف تعريف محدد، مع ربط التأكيد ببايتات المصادقة النشطة الدقيقة التي ستُستبدل.
- تشغيل محلي فقط بلا تحليلات أو قياس عن بُعد.
- إنشاء إصدار Windows متجدد `latest` تلقائياً من `main`.

## تهيئة الحساب وواجهة API المدعومة

| المزود | الملفات المُدارة | التهيئة المُدارة انتقائياً |
| --- | --- | --- |
| Codex | `%USERPROFILE%\.codex\auth.json` و`config.toml` | `model_provider` و`openai_base_url` و`model` و`review_model` و`model_reasoning_effort` و`disable_response_storage` وجدول `model_providers` النشط المحدد و`features.responses_websockets_v2` |
| Claude Code | `%USERPROFILE%\.claude\.credentials.json` و`settings.json` | فقط `env.ANTHROPIC_BASE_URL` و`env.ANTHROPIC_API_KEY` و`env.ANTHROPIC_AUTH_TOKEN` و`env.CLAUDE_CODE_DISABLE_NONESSENTIAL_TRAFFIC` وحقل التوافق `env.CLAUDE_CODE_ATTRIBUTION_HEADER` |
| OpenCode | `%USERPROFILE%\.local\share\opencode\auth.json` اختياري؛ والطبقات العامة `config.json` ثم `opencode.json` ثم `opencode.jsonc`؛ وبعدها `OPENCODE_CONFIG` عند تعيينه | بيانات اعتماد `/connect` المبهمة وملف API الفعلي من `provider` و`model` و`small_model` |

يدمج التطبيق هذه الحقول في التهيئة الحالية ولا يستبدل الملف بالكامل. في Codex تبقى `network_access` و`windows_wsl_setup_acknowledged` و`features.goals` و`cli_auth_credentials_store` وMCP والمهارات والجلسات وكل القيم الأخرى كما هي. وفي Claude Code تبقى بقية قيم `env` و`.claude.json` والمكونات الإضافية وMCP وإعدادات المشاريع والسجل كما هي. وفي OpenCode تبقى القيم الدلالية غير ذات الصلة في كل ملف عام أو مخصص مشارك.

جذر تهيئة OpenCode الافتراضي هو `%USERPROFILE%\.config` وجذر البيانات الافتراضي هو `%USERPROFILE%\.local\share`. تستبدل القيمة المطلقة في `XDG_CONFIG_HOME` أو `XDG_DATA_HOME` الجذر الافتراضي المقابل؛ أما القيمة الفارغة فلا تستبدله. يجب أن تكون كل تجاوزات مسارات OpenCode غير الفارغة (`XDG_CONFIG_HOME` و`XDG_DATA_HOME` و`OPENCODE_CONFIG` و`OPENCODE_CONFIG_DIR`) مسارات مطلقة؛ وتؤدي القيمة النسبية إلى حظر الالتقاط والتبديل قبل كتابة أي ملف. تُقرأ التهيئة العامة بالترتيب من `opencode\config.json` ثم `opencode.json` ثم `opencode.jsonc` تحت جذر التهيئة، وتغلب الطبقات اللاحقة. يُقرأ `OPENCODE_CONFIG` أخيراً. يلتقط التطبيق النتيجة الفعلية لـ `provider` و`model` و`small_model` كملف API واحد. وتُقرأ بيانات اعتماد `/connect` من `opencode\auth.json` تحت جذر البيانات.

يدعم OpenCode بيانات اعتماد `/connect` في `auth.json` ومفاتيح API المضمنة في كائن `provider`؛ وتشمل اللقطة النمط الموجود أو كليهما.

عند التطبيق تُحذف `provider` و`model` و`small_model` من الطبقات العامة الأخرى كي لا تتغلب نقطة قديمة. مع `OPENCODE_CONFIG` تُكتب القيم الهدف فيه وتُنظف الطبقات العامة الثلاث. بدونه تُوحد القيم غير الفارغة في `opencode.jsonc` العام وتُحذف من `config.json` و`opencode.json` حتى إن لم يوجد سابقاً إلا JSON أو الملف القديم. تظل لقطة المصادقة فقط أو التهيئة المُدارة الفارغة صالحة: تنظف القيم الموجودة من دون إنشاء `opencode.jsonc` فارغ.

يحافظ الدمج الانتقائي على القيم الدلالية غير ذات الصلة، لكنه لا يضمن بقاء التنسيق أو التعليقات مطابقين بايتاً ببايت عند إعادة تسلسل JSON أو TOML.

قبل التقاط OpenCode أو تبديله، يفحص التطبيق للقراءة فقط تجاوزات البيئة المعروفة ذات الأولوية الأعلى. تحظر أي قيمة غير فارغة في `OPENCODE_AUTH_CONTENT` العملية. لا يُسمح بـ `OPENCODE_CONFIG_CONTENT` إلا إذا كان JSON أو JSONC صالحاً ولا يحتوي مفاتيح المستوى الأعلى المُدارة `provider` أو `model` أو `small_model`؛ وتحظر العمليةَ تهيئةٌ غير صالحة أو أي من هذه المفاتيح. عند تعيين `OPENCODE_CONFIG_DIR` يفحص التطبيق ملفي `opencode.json` و`opencode.jsonc` فيه؛ ويحظر العملية ملف غير قابل للقراءة أو غير صالح أو يحتوي مفتاحاً مُداراً. يُسمح بتهيئة مضمنة أو في دليل إذا لم تحتوِ إلا مفاتيح غير ذات صلة. ولا يعدّل التطبيق أياً من هذه المصادر التي توفرها البيئة.

يغيّر `CODEX_HOME` و`CLAUDE_CONFIG_DIR` الجذرين المعنيين. تبقى تهيئة مشروع OpenCode والمصادر المُدارة مركزياً ومتغيرات البيئة الخاصة بالمزوّد خارج إدارة التطبيق، وقد تتجاوز الملف العام المحدد بعد التبديل؛ ولا يبحث التطبيق عنها ولا يعدّلها. يفحص حارس العمليات `opencode` و`opencode-cli`. تبقى حقول التوافق من دون ادعاء أنها موثقة في كل الإصدارات الحالية.

يجب أن يستخدم Codex تخزين بيانات اعتماد قائماً على الملفات. إذا كان تثبيتك يستخدم مخزن بيانات اعتماد نظام التشغيل، فأضف الإعداد التالي إلى `config.toml` في جذر Codex النشط (`%USERPROFILE%\.codex` افتراضياً، أو `CODEX_HOME` عند تعيينه):

```toml
cli_auth_credentials_store = "file"
```

راجع وثائق [مصادقة Codex](https://developers.openai.com/codex/auth) و[مصادقة Claude Code](https://code.claude.com/docs/en/authentication) الرسمية لمعرفة عقود التخزين الحالية.

## طريقة العمل

1. سجّل الدخول عبر المسار الرسمي أو هيئ موقع API مدعوماً في ملفات المزود المعتادة.
2. أغلق Codex وClaude Code وOpenCode وأي عميل أو إضافة ذات صلة تماماً.
3. احفظ الحساب وإعدادات API المُدارة باسم مثل `Personal`.
4. سجّل الدخول إلى حساب آخر أو هيئ موقع API آخر واحفظه باسم `Work`.
5. اختر ملف تعريف. إذا كانت عملية ذات صلة قيد التشغيل، يُمنع التبديل ولا يُعدّل أي ملف مُدار.
6. بعد تأكيد مرتبط بالمحتوى، تُحفظ اللقطة المُدارة الحالية في آخر ملف تعريف مشفر للاحتفاظ بالرموز المحدثة وتغييرات API المقصودة. وتُحفظ اللقطة الدقيقة السابقة أيضاً في كتلة استرداد DPAPI خاصة بالمعاملة.

يسمّي التطبيق ملف التعريف هذا **آخر ملف تعريف محدد** وليس «الحالي المتحقق منه». إذا لم يعد ملف التعريف النشط يطابق لقطته المحفوظة، يتوقف التبديل قبل أي كتابة. أكّد فقط عندما يكون التغيير تحديثاً للحساب نفسه. إذا سجلت الدخول إلى حساب مختلف خارج التطبيق، فاختر أولاً **حفظ كملف تعريف جديد** (أو استبدل صراحةً ملف التعريف الموجود ذي الاسم الصحيح).

يتحقق زر **استعادة اللقطة** في بطاقة آخر ملف تعريف محدد مما إذا كان ملف التعريف النشط لا يزال يطابق اللقطة المحفوظة. إذا اختلف، يحذر التطبيق من استبدال تسجيل الدخول الحالي غير المحفوظ ويربط الموافقة بتلك البايتات الدقيقة. لا يمكن لتسجيل دخول نشط مختلف إعادة استخدام تأكيد سابق. أثناء الاستعادة، تحتفظ بيانات اعتماد استرداد خاصة بالمعاملة ومشفرة بـ DPAPI بالبايتات السابقة حتى تثبيت العملية أو التراجع عنها.

تكتب كل معاملة مركبة أو متعددة الملفات اللقطة المُدارة الحالية الدقيقة في كتلة الاسترداد المشفرة قبل السجل، حتى عندما تطابق المصدر المحفوظ. يتيح ذلك التراجع الدقيق عن كتابة جزئية وترقية ملف مصدر قديم لا يحتوي إلا على بيانات الاعتماد بأمان. بعد الانقطاع، تفضّل آلية الاسترداد لقطة ما قبل التبديل هذه وتزامن ملف المصدر إذا أعادتها. ترجع السجلات القديمة بلا كتلة إلى المصدر المحفوظ. إذا لم تطابق الحالة المُدارة النشطة المصدر ولا الهدف، يبقى السجل والكتلة للاسترداد اليدوي.

تُغلق عملية تثبيت الملفات المتعددة عند الفشل: تُحذف المصادقة المنفصلة أولاً، ثم تُدمج التهيئة ذرياً، وتُثبت مصادقة الهدف أخيراً. قد تترك المقاطعة المصادقة غائبة مؤقتاً، لكنها لا تقرن بيانات الاعتماد بنقطة API لملف التعريف المقابل؛ ويُكمل الاسترداد أو يتراجع بأمان من لقطة ما قبل التبديل المشفرة.

تُفسر ملفات تعريف Codex وClaude Code الخام القديمة على أنها بيانات اعتماد مع تهيئة API مُدارة فارغة. يؤدي تنشيطها إلى مسح حقول مسار API والنموذج المُدارة كي لا تعيد استخدام نقطة خارجية من ملف التعريف السابق. بعد التنشيط، اضبط النموذج/API المطلوب وأعد التقاط الملف. ويُرقى المصدر القديم النشط إلى التنسيق المركب عند التبديل عنه.

لا يضمن التطبيق بقاء تسجيل الدخول بشكل دائم. قد يفرض الإلغاء من جهة المزود أو سياسة المؤسسة أو SSO أو MFA أو انتهاء الرمز تسجيل دخول عادي عبر العميل الرسمي.

## الإعدادات

افتح **الإعدادات** من نافذة التطبيق لاختيار لغة العرض أو التحكم في بدء التطبيق مع Windows. تُحفظ اللغة المحددة محلياً للمستخدم الحالي في Windows ويمكن تغييرها في أي وقت.

يضيف خيار **البدء مع Windows** إدخالاً لهذا التطبيق ضمن `HKCU\Software\Microsoft\Windows\CurrentVersion\Run`. ينطبق على مستخدم Windows الحالي فقط ولا يتطلب صلاحيات المسؤول. يؤدي إيقافه إلى إزالة إدخال بدء التشغيل الخاص بـ Coding Agent Account Switcher وحده، ولا يغير تطبيقات بدء التشغيل الأخرى.

## نموذج الأمان

- تُخزن بيانات ملفات التعريف المشفرة تحت `%LOCALAPPDATA%\CodingAgentAccountSwitcher`.
- لكل مجموعة مطبّعة من الملفات المُدارة خزنة وحالة وسجل استرداد وقفل مستقل. يؤدي تغيير `CODEX_HOME` أو `CLAUDE_CONFIG_DIR` أو `OPENCODE_CONFIG` إلى بدء مجموعة ملفات تعريف أخرى.
- يمنع DPAPI `CurrentUser` حساب Windows آخر من فك تشفير ملف التعريف مباشرةً، لكنه لا يحمي من البرامج الضارة التي تعمل بالفعل باسم مستخدم Windows نفسه.
- باستثناء ملف المصادقة النشط العادي للمزود، لا توجد بايتات اللقطة المفكوكة إلا لفترة وجيزة في الذاكرة وفي الاستبدال الذري داخل المجلد نفسه أثناء الالتقاط أو التبديل.
- تستخدم ملفات الاستبدال المؤقتة والنسخ الاحتياطية معرّف معاملة الاسترداد. يحذف الإكمال العادي كلا الملفين المحددين. بعد الانقطاع، تستعيد آلية الاسترداد ملفاً نشطاً مفقوداً من لقطة المصدر المشفرة أو بيانات اعتماد الاسترداد الخاصة بالمعاملة، ثم تزيل كل ملفات التجهيز المحددة التي تملكها المعاملة قبل حذف السجل. لا تُحذف كتلة الاسترداد المشفرة إلا بعد السجل، وذلك على أساس بذل أفضل جهد.
- لا يرفع التطبيق بيانات الاعتماد، ويجب ألا تُدرج أبداً في سجل أو مشكلة أو تقرير تعطل أو بيانات اختبار أو تثبيت في المستودع.
- كشف العمليات إجراء دفاعي وفق أفضل جهد؛ لا تشغّل Codex أو Claude Code أو OpenCode حتى تكتمل العملية.
- إذا كانت المؤسسة تدير حساب العمل، فاحصل على موافقتها قبل الاحتفاظ بلقطة مصادقة محلية مشفرة إضافية.

اقرأ [SECURITY.md](SECURITY.md) و[docs/ARCHITECTURE.md](docs/ARCHITECTURE.md) قبل تغيير الشفرة التي تتعامل مع بيانات الاعتماد.

## البناء من المصدر

المتطلبات:

- Windows 10 أو Windows 11
- .NET SDK 8.0.400 أو feature band أحدث من .NET 8

```powershell
dotnet restore CodingAgentAccountSwitcher.sln
dotnet test CodingAgentAccountSwitcher.sln --configuration Release
dotnet run --project .\src\CodingAgentAccountSwitcher.App\CodingAgentAccountSwitcher.App.csproj
```

إنشاء بناء Windows x64 مستقل:

```powershell
dotnet publish .\src\CodingAgentAccountSwitcher.App\CodingAgentAccountSwitcher.App.csproj `
  --configuration Release `
  --runtime win-x64 `
  --self-contained true `
  --output .\artifacts\publish
```

## إصدار latest المتجدد

يعمل `.github/workflows/latest-release.yml` عند كل دفع إلى `main`:

1. يستعيد الحل ويختبره.
2. ينشر بناء Windows x64 محمولاً ومستقلاً.
3. ينشئ مثبّت Windows x64 خاصاً بالمستخدم الحالي.
4. يجهّز الملف التنفيذي المحمول ومجاميع تحقق SHA-256 لكلا الملفين التنفيذيين.
5. يحذف الإصدار والوسم السابقين المسميين `latest` فقط.
6. ينشر إصدار `latest` جديداً للالتزام الحالي مع المثبّت والملف التنفيذي المحمول ومجاميع التحقق.

لا يحذف سير العمل هذا الإصدارات المرقمة أبداً. يجب أن يظل خيار GitHub المسمى **immutable releases** معطلاً لوسم `latest` المتجدد، وأن تسمح قواعد الفروع أو الوسوم لسير العمل بحذف `latest`. ينبغي للمستودعات التي تتطلب إصدارات غير قابلة للتغيير استخدام وسوم بناء فريدة.

المثبّت والملف التنفيذي المحمول في الإصدار المتجدد غير موقّعين حالياً، لذلك قد يعرض Windows SmartScreen تحذيراً متعلقاً بالسمعة. راجع المصدر وتحقق من مجموع SHA-256 المنشور والمطابق قبل تشغيل أي من الملفين التنفيذيين.
