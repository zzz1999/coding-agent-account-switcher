# Coding Agent Account Switcher

[English](README.md) · [简体中文](README.zh-CN.md) · [繁體中文](README.zh-TW.md) · [Español](README.es.md) · [Français](README.fr.md) · [Deutsch](README.de.md) · [日本語](README.ja.md) · [한국어](README.ko.md) · [Português (Brasil)](README.pt-BR.md) · [Русский](README.ru.md) · [العربية](README.ar.md) · [हिन्दी](README.hi.md)

Codex, Claude Code और OpenCode के लिए एक अनौपचारिक, लोकल-फर्स्ट Windows खाता तथा API साइट स्विचर।

Coding Agent Account Switcher स्थानीय क्रेडेंशियल के साथ केवल आवश्यक API प्रदाता फ़ील्ड के एन्क्रिप्टेड स्नैपशॉट सहेजता है। बाकी सेटिंग्स, MCP, स्किल्स, प्लगइन और प्रोजेक्ट इतिहास अपने मूल स्थानों पर बने रहते हैं।

> [!IMPORTANT]
> यह प्रोजेक्ट OpenAI या Anthropic से संबद्ध, उनके द्वारा समर्थित या प्रायोजित नहीं है। यह सदस्यता स्थानांतरित नहीं करता, साइन-इन आवश्यकताओं को बायपास नहीं करता, खाते साझा नहीं करता और प्रदाता या संगठन की नीतियों से बचने का साधन नहीं है।

“iOS 18 से प्रेरित” विवरण केवल सामान्य दृश्य दिशा को दर्शाता है। Apple इस प्रोजेक्ट से संबद्ध नहीं है और इसमें Apple के फ़ॉन्ट, प्रतीक, कलाकृतियाँ या ट्रेडमार्क शामिल नहीं हैं।

## डाउनलोड

मौजूदा बिल्ड को [latest रिलीज़](https://github.com/zzz1999/coding-agent-account-switcher/releases/latest) से डाउनलोड करें:

- **अनुशंसित इंस्टॉलर:** `coding-agent-account-switcher-setup-win-x64.exe` बिना एडमिनिस्ट्रेटर अधिकार के मौजूदा Windows उपयोगकर्ता के लिए इंस्टॉल करता है और स्टार्ट मेनू व अनइंस्टॉल प्रविष्टियाँ बनाता है।
- **पोर्टेबल एक्ज़ीक्यूटेबल:** `coding-agent-account-switcher-portable-win-x64.exe` को सीधे डाउनलोड करके चलाएँ; इंस्टॉल करने की आवश्यकता नहीं है।
- रिलीज़ में प्रत्येक एक्ज़ीक्यूटेबल के लिए उससे मेल खाती SHA-256 चेकसम फ़ाइल शामिल होती है।

इंस्टॉलर **Windows के साथ शुरू करें** विकल्प को अपने-आप सक्षम नहीं करता और Codex, Claude Code या OpenCode की प्रमाणीकरण अथवा कॉन्फ़िगरेशन फ़ाइलों को नहीं छूता। अनइंस्टॉल करने पर एन्क्रिप्ट किए गए खाता स्नैपशॉट और ऐप सेटिंग्स सुरक्षित रहते हैं, ताकि दोबारा इंस्टॉल करने के बाद भी उपलब्ध रहें। इंस्टॉलर और पोर्टेबल एक्ज़ीक्यूटेबल अभी हस्ताक्षरित नहीं हैं, इसलिए Windows SmartScreen प्रतिष्ठा चेतावनी दिखा सकता है।

## विशेषताएँ

- iOS 18 से प्रेरित ग्लास-कार्ड डिज़ाइन वाला Windows-नेटिव WPF इंटरफ़ेस।
- अंग्रेज़ी, सरलीकृत चीनी, पारंपरिक चीनी, स्पैनिश, फ़्रेंच, जर्मन, जापानी, कोरियाई, ब्राज़ीलियाई पुर्तगाली, रूसी, अरबी और हिन्दी के अंतर्निहित इंटरफ़ेस।
- डिस्प्ले भाषा और वर्तमान उपयोगकर्ता के लिए वैकल्पिक Windows स्टार्टअप की इन-ऐप सेटिंग्स।
- Codex, Claude Code और OpenCode के लिए नामयुक्त निजी, कार्य और API साइट प्रोफ़ाइल।
- संबंधित एप्लिकेशन बंद होने तक स्विच को रोकने वाला प्रोसेस गार्ड।
- प्रमाणीकरण फ़ाइलें अपारदर्शी बाइट्स रहती हैं। केवल नीचे सूचीबद्ध प्रबंधित फ़ील्ड पार्स और मर्ज होते हैं; रहस्य कभी दिखाए या लॉग नहीं किए जाते।
- वर्तमान Windows उपयोगकर्ता के लिए Windows DPAPI से एन्क्रिप्ट किए गए प्रोफ़ाइल स्नैपशॉट।
- रोलबैक समर्थन के साथ उसी डायरेक्टरी में प्रबंधित फ़ाइलों का एटॉमिक प्रतिस्थापन।
- बदला हुआ लाइव लॉगिन अंतिम चुने गए प्रोफ़ाइल स्नैपशॉट को ओवरराइट कर सके, उससे पहले स्पष्ट पुष्टि।
- अंतिम चुने गए प्रोफ़ाइल के लिए सुरक्षित **स्नैपशॉट पुनर्स्थापित करें** क्रिया, जिसमें पुष्टि बदले जाने वाले लाइव प्रमाणीकरण के सटीक बाइट्स से बंधी होती है।
- बिना एनालिटिक्स या टेलीमेट्री के केवल स्थानीय संचालन।
- `main` से स्वतः तैयार होने वाला रोलिंग Windows `latest` बिल्ड।

## समर्थित खाता और API कॉन्फ़िगरेशन

| प्रदाता | प्रबंधित फ़ाइलें | चुनिंदा रूप से प्रबंधित कॉन्फ़िगरेशन |
| --- | --- | --- |
| Codex | `%USERPROFILE%\.codex\auth.json` और `config.toml` | `model_provider`, `openai_base_url`, `model`, `review_model`, `model_reasoning_effort`, `disable_response_storage`, चुनी हुई सक्रिय `model_providers` तालिका और `features.responses_websockets_v2` |
| Claude Code | `%USERPROFILE%\.claude\.credentials.json` और `settings.json` | केवल `env.ANTHROPIC_BASE_URL`, `env.ANTHROPIC_API_KEY`, `env.ANTHROPIC_AUTH_TOKEN`, `env.CLAUDE_CODE_DISABLE_NONESSENTIAL_TRAFFIC` और संगतता फ़ील्ड `env.CLAUDE_CODE_ATTRIBUTION_HEADER` |
| OpenCode | वैकल्पिक `%USERPROFILE%\.local\share\opencode\auth.json`; वैश्विक `config.json`, `opencode.json`, `opencode.jsonc`; सेट होने पर अंत में `OPENCODE_CONFIG` | अपारदर्शी `/connect` क्रेडेंशियल और प्रभावी `provider`, `model`, `small_model` API प्रोफ़ाइल |

एप्लिकेशन पूरी फ़ाइल को बदलने के बजाय इन फ़ील्ड को वर्तमान कॉन्फ़िगरेशन में मर्ज करता है। Codex में `network_access`, `windows_wsl_setup_acknowledged`, `features.goals`, `cli_auth_credentials_store`, MCP, स्किल्स, सेशन और अन्य सभी मान सुरक्षित रहते हैं। Claude Code में बाकी `env`, `.claude.json`, प्लगइन, MCP, प्रोजेक्ट सेटिंग्स और इतिहास सुरक्षित रहते हैं। OpenCode में हर सहभागी वैश्विक या कस्टम फ़ाइल के असंबंधित अर्थपूर्ण मान सुरक्षित रहते हैं।

OpenCode का डिफ़ॉल्ट कॉन्फ़िगरेशन रूट `%USERPROFILE%\.config` और डिफ़ॉल्ट डेटा रूट `%USERPROFILE%\.local\share` है। `XDG_CONFIG_HOME` या `XDG_DATA_HOME` का निरपेक्ष पथ संबंधित डिफ़ॉल्ट रूट को बदलता है; खाली मान उसे नहीं बदलता। OpenCode के सभी गैर-खाली पथ ओवरराइड (`XDG_CONFIG_HOME`, `XDG_DATA_HOME`, `OPENCODE_CONFIG` और `OPENCODE_CONFIG_DIR`) निरपेक्ष पथ होने चाहिए; सापेक्ष मान किसी भी फ़ाइल में लिखने से पहले कैप्चर और स्विच को रोक देता है। वैश्विक कॉन्फ़िगरेशन, कॉन्फ़िगरेशन रूट के नीचे `opencode\config.json`, फिर `opencode.json`, फिर `opencode.jsonc` से पढ़ा जाता है; बाद की परत पहले को ओवरराइड करती है। `OPENCODE_CONFIG` सबसे अंत में पढ़ा जाता है। ऐप प्रभावी `provider`, `model` और `small_model` को एक API प्रोफ़ाइल के रूप में कैप्चर करता है। `/connect` क्रेडेंशियल डेटा रूट के नीचे `opencode\auth.json` से पढ़े जाते हैं।

OpenCode `auth.json` में `/connect` क्रेडेंशियल और `provider` ऑब्जेक्ट में API कुंजी—दोनों का समर्थन करता है; स्नैपशॉट मौजूद शैली या दोनों को शामिल करता है।

लागू करते समय पुराने निचले एंडपॉइंट को प्रभावी होने से रोकने के लिए अन्य वैश्विक परतों से `provider`, `model` और `small_model` हटते हैं। `OPENCODE_CONFIG` होने पर लक्ष्य वहीं लिखा जाता है और तीनों वैश्विक परतें साफ़ होती हैं। उसके बिना गैर-खाली लक्ष्य वैश्विक `opencode.jsonc` में सामान्यीकृत होता है और पहले केवल JSON/पुरानी फ़ाइल होने पर भी `config.json` तथा `opencode.json` से हटता है। केवल प्रमाणीकरण या खाली प्रबंधित स्नैपशॉट मान्य है: यह मौजूदा मान साफ़ करता है, पर नया खाली `opencode.jsonc` नहीं बनाता।

चुनिंदा मर्ज असंबंधित अर्थपूर्ण मान सुरक्षित रखता है, लेकिन JSON या TOML दोबारा सीरियलाइज़ होने पर फ़ॉर्मेटिंग या टिप्पणियाँ बाइट-दर-बाइट सुरक्षित रहने की गारंटी नहीं देता।

OpenCode को कैप्चर या स्विच करने से पहले ऐप ज्ञात उच्च-प्राथमिकता पर्यावरण ओवरराइड को केवल पढ़कर जाँचता है। `OPENCODE_AUTH_CONTENT` में गैर-रिक्त मान होने पर कार्रवाई रुक जाती है। `OPENCODE_CONFIG_CONTENT` तभी अनुमत है जब वह वैध JSON/JSONC हो और उसमें शीर्ष-स्तरीय प्रबंधित कुंजियाँ `provider`, `model` या `small_model` न हों; अमान्य सामग्री या ऐसी कोई कुंजी कार्रवाई रोक देती है। `OPENCODE_CONFIG_DIR` सेट होने पर उसके `opencode.json` और `opencode.jsonc` जाँचे जाते हैं; अपठनीय या अमान्य फ़ाइल अथवा किसी प्रबंधित कुंजी वाली फ़ाइल कार्रवाई रोक देती है। केवल असंबंधित कुंजियों वाला इनलाइन या डायरेक्टरी कॉन्फ़िगरेशन अनुमत है। ऐप पर्यावरण से मिले इन स्रोतों को बदलता नहीं है।

`CODEX_HOME` और `CLAUDE_CONFIG_DIR` संबंधित रूट बदलते हैं। OpenCode का प्रोजेक्ट कॉन्फ़िगरेशन, केंद्रीय रूप से प्रबंधित स्रोत और प्रदाता-विशिष्ट पर्यावरण चर ऐप के प्रबंधन से बाहर रहते हैं और स्विच के बाद चुनी गई वैश्विक प्रोफ़ाइल को ओवरराइड कर सकते हैं; ऐप उन्हें खोजता या बदलता नहीं है। प्रोसेस गार्ड `opencode` और `opencode-cli` दोनों जाँचता है। संगतता फ़ील्ड का अर्थ यह नहीं कि हर वर्तमान संस्करण उन्हें दस्तावेज़ित करता है।

Codex को फ़ाइल-आधारित क्रेडेंशियल स्टोरेज का उपयोग करना चाहिए। यदि आपकी स्थापना ऑपरेटिंग सिस्टम क्रेडेंशियल स्टोर का उपयोग करती है, तो सक्रिय Codex रूट (डिफ़ॉल्ट रूप से `%USERPROFILE%\.codex`, या सेट होने पर `CODEX_HOME`) की `config.toml` फ़ाइल में यह सेटिंग जोड़ें:

```toml
cli_auth_credentials_store = "file"
```

वर्तमान स्टोरेज अनुबंधों के लिए आधिकारिक [Codex प्रमाणीकरण दस्तावेज़](https://developers.openai.com/codex/auth) और [Claude Code प्रमाणीकरण दस्तावेज़](https://code.claude.com/docs/en/authentication) देखें।

## यह कैसे काम करता है

1. आधिकारिक फ़्लो से साइन इन करें या सामान्य प्रदाता फ़ाइलों में समर्थित API साइट कॉन्फ़िगर करें।
2. Codex, Claude Code, OpenCode और संबंधित क्लाइंट या एक्सटेंशन पूरी तरह बंद करें।
3. खाते और प्रबंधित API सेटिंग्स को `Personal` जैसे नाम से सहेजें।
4. दूसरा खाता या API साइट कॉन्फ़िगर करके उसे `Work` जैसे नाम से सहेजें।
5. प्रोफ़ाइल चुनें। संबंधित प्रोसेस चल रहा हो तो स्विच रुकता है और कोई प्रबंधित फ़ाइल नहीं बदलती।
6. सामग्री से बंधी पुष्टि के बाद वर्तमान प्रबंधित स्नैपशॉट अंतिम चुनी गई एन्क्रिप्टेड प्रोफ़ाइल में सहेजा जाता है, ताकि रीफ़्रेश टोकन और जानबूझकर किए API बदलाव बने रहें। सटीक पिछला स्नैपशॉट भी ट्रांज़ैक्शन-विशिष्ट DPAPI रिकवरी ब्लॉब में सुरक्षित रहता है।

ऐप इस प्रोफ़ाइल को “सत्यापित वर्तमान” नहीं बल्कि **अंतिम चयनित** कहता है। यदि लाइव फ़ाइल अपने सहेजे गए स्नैपशॉट से मेल नहीं खाती, तो स्विच किसी भी लेखन से पहले रुक जाता है। केवल तभी पुष्टि करें जब बदलाव उसी खाते का रीफ़्रेश हो। यदि आपने ऐप के बाहर किसी अलग खाते में साइन इन किया है, तो पहले **नए के रूप में सहेजें** चुनें (या सही नाम वाली मौजूदा प्रोफ़ाइल को स्पष्ट रूप से बदलें)।

अंतिम चयनित कार्ड का **स्नैपशॉट पुनर्स्थापित करें** बटन जाँचता है कि लाइव फ़ाइल अभी भी सहेजे गए स्नैपशॉट से मेल खाती है या नहीं। अलग होने पर ऐप चेतावनी देता है कि वर्तमान बिना-सहेजा लॉगिन बदल दिया जाएगा और अनुमति को उन्हीं सटीक बाइट्स से बाँधता है। कोई अलग लाइव लॉगिन पिछली पुष्टि का दोबारा उपयोग नहीं कर सकता। पुनर्स्थापना के दौरान केवल उस ट्रांज़ैक्शन के लिए DPAPI-एन्क्रिप्टेड रिकवरी क्रेडेंशियल, ऑपरेशन के कमिट या रोलबैक होने तक पुराने बाइट्स सुरक्षित रखता है।

हर संयुक्त या बहु-फ़ाइल ट्रांज़ैक्शन, वर्तमान प्रबंधित स्नैपशॉट के सहेजे स्रोत से मेल खाने पर भी, जर्नल से पहले उसका सटीक रूप एन्क्रिप्टेड रिकवरी ब्लॉब में लिखता है। इससे आंशिक फ़ाइल लेखन ठीक-ठीक वापस हो सकता है और केवल क्रेडेंशियल वाली पुरानी स्रोत प्रोफ़ाइल सुरक्षित रूप से अपग्रेड होती है। रुकावट के बाद रिकवरी इस प्री-स्विच स्नैपशॉट को प्राथमिकता देती है और उसे पुनर्स्थापित करने पर स्रोत प्रोफ़ाइल सिंक्रोनाइज़ करती है। ब्लॉब के बिना पुराने जर्नल सहेजे स्रोत पर लौटते हैं। लाइव प्रबंधित स्थिति स्रोत या लक्ष्य से न मिले तो जर्नल और ब्लॉब मैनुअल रिकवरी के लिए रखे जाते हैं।

बहु-फ़ाइल कमिट विफल होने पर बंद रहता है: अलग प्रमाणीकरण पहले हटता है, कॉन्फ़िगरेशन एटॉमिक रूप से मर्ज होता है और लक्ष्य प्रमाणीकरण सबसे अंत में स्थापित होता है। रुकावट से प्रमाणीकरण अस्थायी रूप से गायब हो सकता है, लेकिन क्रेडेंशियल विपरीत प्रोफ़ाइल के API एंडपॉइंट से नहीं जुड़ते; एन्क्रिप्टेड प्री-स्विच स्नैपशॉट से रिकवरी सुरक्षित रूप से पूरा या रोलबैक करती है।

पुरानी कच्ची Codex और Claude Code प्रोफ़ाइल को क्रेडेंशियल और खाली प्रबंधित API कॉन्फ़िगरेशन माना जाता है। उसे सक्रिय करने पर प्रबंधित API रूट और मॉडल फ़ील्ड साफ़ होते हैं, ताकि पिछली प्रोफ़ाइल का तृतीय-पक्ष एंडपॉइंट दोबारा उपयोग न हो। फिर इच्छित मॉडल/API सेट करके प्रोफ़ाइल दोबारा कैप्चर करें। पुराना सक्रिय स्रोत उससे स्विच करते समय संयुक्त फ़ॉर्मेट में अपग्रेड होता है।

ऐप स्थायी लॉगिन का वादा नहीं करता। प्रदाता द्वारा रद्द करना, संगठन नीति, SSO, MFA या टोकन की समय-सीमा समाप्त होना अभी भी आधिकारिक क्लाइंट से सामान्य साइन-इन आवश्यक बना सकता है।

## सेटिंग्स

डिस्प्ले भाषा चुनने या ऐप के Windows के साथ शुरू होने को नियंत्रित करने के लिए ऐप विंडो से **सेटिंग्स** खोलें। चुनी गई भाषा वर्तमान Windows उपयोगकर्ता के लिए स्थानीय रूप से सहेजी जाती है और कभी भी बदली जा सकती है।

**Windows के साथ शुरू करें** इस एप्लिकेशन की एक प्रविष्टि `HKCU\Software\Microsoft\Windows\CurrentVersion\Run` में जोड़ता है। यह केवल वर्तमान Windows उपयोगकर्ता पर लागू होता है और इसके लिए व्यवस्थापक अधिकारों की आवश्यकता नहीं है। विकल्प बंद करने पर केवल Coding Agent Account Switcher की अपनी स्टार्टअप प्रविष्टि हटती है; अन्य स्टार्टअप एप्लिकेशन नहीं बदलते।

## सुरक्षा मॉडल

- एन्क्रिप्टेड प्रोफ़ाइल डेटा `%LOCALAPPDATA%\CodingAgentAccountSwitcher` के अंतर्गत रखा जाता है।
- हर सामान्यीकृत प्रबंधित फ़ाइल समूह के लिए अलग वॉल्ट, स्थिति, रिकवरी जर्नल और म्यूटेक्स होता है। `CODEX_HOME`, `CLAUDE_CONFIG_DIR` या `OPENCODE_CONFIG` बदलने पर अलग प्रोफ़ाइल समूह शुरू होता है।
- DPAPI `CurrentUser` किसी अन्य Windows खाते को प्रोफ़ाइल सीधे डिक्रिप्ट करने से रोकता है, लेकिन पहले से उसी Windows उपयोगकर्ता के रूप में चल रहे दुर्भावनापूर्ण सॉफ़्टवेयर से रक्षा नहीं कर सकता।
- प्रदाता की सामान्य लाइव प्रमाणीकरण फ़ाइल को छोड़कर, डिक्रिप्ट किए गए स्नैपशॉट बाइट्स कैप्चर या स्विच के दौरान केवल थोड़ी देर के लिए मेमोरी और उसी डायरेक्टरी की एटॉमिक प्रतिस्थापन प्रक्रिया में रहते हैं।
- प्रमाणीकरण प्रतिस्थापन की अस्थायी और बैकअप फ़ाइलें रिकवरी ट्रांज़ैक्शन ID का उपयोग करती हैं। सामान्य समापन दोनों सटीक फ़ाइलें हटा देता है। रुकावट के बाद रिकवरी एन्क्रिप्टेड स्रोत स्नैपशॉट या ट्रांज़ैक्शन-विशिष्ट रिकवरी क्रेडेंशियल से गुम लाइव फ़ाइल पुनर्स्थापित करती है, फिर जर्नल हटाने से पहले उसी ट्रांज़ैक्शन की सभी सटीक स्टेजिंग फ़ाइलें हटाती है। एन्क्रिप्टेड रिकवरी ब्लॉब को जर्नल के बाद ही, सर्वोत्तम प्रयास के आधार पर हटाया जाता है।
- ऐप क्रेडेंशियल अपलोड नहीं करता। उन्हें कभी भी लॉग, इश्यू, क्रैश रिपोर्ट, परीक्षण डेटा या रिपॉज़िटरी कमिट में शामिल नहीं किया जाना चाहिए।
- प्रोसेस पहचान एक रक्षात्मक, सर्वोत्तम-प्रयास उपाय है। ऑपरेशन पूरा होने तक Codex, Claude Code या OpenCode शुरू न करें।
- यदि कार्य खाता किसी संगठन द्वारा प्रबंधित है, तो अतिरिक्त एन्क्रिप्टेड स्थानीय प्रमाणीकरण स्नैपशॉट रखने से पहले अनुमति लें।

क्रेडेंशियल संभालने वाले कोड में बदलाव से पहले [SECURITY.md](SECURITY.md) और [docs/ARCHITECTURE.md](docs/ARCHITECTURE.md) पढ़ें।

- .NET SDK 8.0.400 या कोई नया .NET 8 feature band

dotnet restore CodingAgentAccountSwitcher.sln

## रोलिंग latest रिलीज़

`main` पर हर push के लिए `.github/workflows/latest-release.yml` चलता है:

1. समाधान को रीस्टोर और टेस्ट करता है।
2. स्व-निहित पोर्टेबल Windows x64 बिल्ड प्रकाशित करता है।
3. प्रति-उपयोगकर्ता Windows x64 इंस्टॉलर बनाता है।
4. पोर्टेबल एक्ज़ीक्यूटेबल और दोनों एक्ज़ीक्यूटेबल के SHA-256 चेकसम तैयार करता है।
5. केवल पिछली `latest` नामक रिलीज़ और टैग हटाता है।
6. मौजूदा कमिट के लिए इंस्टॉलर, पोर्टेबल एक्ज़ीक्यूटेबल और चेकसम सहित नई `latest` रिलीज़ प्रकाशित करता है।

यह वर्कफ़्लो संस्करणयुक्त रिलीज़ कभी नहीं हटाता। रोलिंग `latest` टैग के लिए GitHub का **immutable releases** विकल्प अक्षम रहना चाहिए, और ब्रांच या टैग नियमों को वर्कफ़्लो द्वारा `latest` हटाने की अनुमति देनी चाहिए। अपरिवर्तनीय रिलीज़ की आवश्यकता वाले रिपॉज़िटरी को अलग-अलग बिल्ड टैग इस्तेमाल करने चाहिए।

रोलिंग इंस्टॉलर और पोर्टेबल एक्ज़ीक्यूटेबल अभी हस्ताक्षरित नहीं हैं, इसलिए Windows SmartScreen प्रतिष्ठा चेतावनी दिखा सकता है। किसी भी एक्ज़ीक्यूटेबल को चलाने से पहले स्रोत की समीक्षा करें और उससे मेल खाता प्रकाशित SHA-256 चेकसम सत्यापित करें।
