# Coding Agent Account Switcher

[English](README.md) · [简体中文](README.zh-CN.md) · [繁體中文](README.zh-TW.md) · [Español](README.es.md) · [Français](README.fr.md) · [Deutsch](README.de.md) · [日本語](README.ja.md) · [한국어](README.ko.md) · [Português (Brasil)](README.pt-BR.md) · [Русский](README.ru.md) · [العربية](README.ar.md) · [हिन्दी](README.hi.md)

Неофициальное локальное Windows-приложение для переключения учётных записей и API-сервисов Codex, Claude Code и OpenCode.

Coding Agent Account Switcher сохраняет зашифрованные снимки локальных учётных данных вместе только с необходимыми полями поставщика API. Остальные настройки, MCP, навыки, плагины и история проектов остаются в исходных расположениях.

> [!IMPORTANT]
> Этот проект не связан с OpenAI или Anthropic, не одобрен и не спонсируется ими. Он не переносит подписки, не обходит требования входа, не обеспечивает совместное использование учётных записей и не позволяет обходить правила поставщика или организации.

Фраза «в стиле iOS 18» описывает только общее визуальное направление. Apple не связана с проектом; шрифты, символы, иллюстрации и товарные знаки Apple в него не входят.

## Скачать

Загрузите текущую сборку из [выпуска latest](https://github.com/zzz1999/coding-agent-account-switcher/releases/latest):

- **Рекомендуемый установщик:** `coding-agent-account-switcher-setup-win-x64.exe` устанавливает приложение для текущего пользователя Windows без прав администратора и создаёт пункты меню «Пуск» и удаления.
- **Портативный исполняемый файл:** загрузите `coding-agent-account-switcher-portable-win-x64.exe` и запустите его напрямую; установка не требуется.
- В выпуске для каждого исполняемого файла предоставляется соответствующий файл контрольной суммы SHA-256.

Установщик не включает **Запускать вместе с Windows** автоматически и не изменяет файлы аутентификации или конфигурации Codex, Claude Code и OpenCode. При удалении приложения зашифрованные снимки учётных записей и настройки сохраняются, поэтому они остаются доступными после повторной установки. Установщик и портативный исполняемый файл пока не подписаны, поэтому Windows SmartScreen может показать предупреждение о репутации.

## Возможности

- Нативный интерфейс WPF для Windows с оформлением стеклянных карточек в стиле iOS 18.
- Встроенные языки интерфейса: английский, упрощённый и традиционный китайский, испанский, французский, немецкий, японский, корейский, бразильский португальский, русский, арабский и хинди.
- Настройки языка интерфейса и необязательного запуска вместе с Windows для текущего пользователя.
- Именованные личные, рабочие и API-профили для Codex, Claude Code и OpenCode.
- Защита по процессам: переключение блокируется, пока связанные приложения не закрыты.
- Файлы аутентификации остаются непрозрачными байтами. Разбираются и объединяются только перечисленные ниже управляемые поля; секреты никогда не отображаются и не записываются в журнал.
- Снимки профилей шифруются Windows DPAPI для текущего пользователя Windows.
- Атомарная замена управляемых файлов в том же каталоге с поддержкой отката.
- Явное подтверждение перед тем, как изменённый активный вход перезапишет снимок последнего выбранного профиля.
- Безопасное действие **Восстановить снимок** для последнего выбранного профиля; подтверждение привязывается к точным байтам активной аутентификации, которые будут заменены.
- Полностью локальная работа без аналитики и телеметрии.
- Автоматическая скользящая сборка `latest` для Windows из ветки `main`.

## Поддерживаемая конфигурация учётной записи и API

| Поставщик | Управляемые файлы | Выборочно управляемая конфигурация |
| --- | --- | --- |
| Codex | `%USERPROFILE%\.codex\auth.json` и `config.toml` | `model_provider`, `openai_base_url`, `model`, `review_model`, `model_reasoning_effort`, `disable_response_storage`, выбранная активная таблица `model_providers` и `features.responses_websockets_v2` |
| Claude Code | `%USERPROFILE%\.claude\.credentials.json` и `settings.json` | Только `env.ANTHROPIC_BASE_URL`, `env.ANTHROPIC_API_KEY`, `env.ANTHROPIC_AUTH_TOKEN`, `env.CLAUDE_CODE_DISABLE_NONESSENTIAL_TRAFFIC` и поле совместимости `env.CLAUDE_CODE_ATTRIBUTION_HEADER` |
| OpenCode | Необязательный `%USERPROFILE%\.local\share\opencode\auth.json`; глобальные слои `config.json`, `opencode.json`, `opencode.jsonc`; затем `OPENCODE_CONFIG`, если задан | Непрозрачные данные `/connect` и эффективный API-профиль `provider`, `model`, `small_model` |

Приложение объединяет эти поля с текущей конфигурацией, а не заменяет весь файл. В Codex сохраняются `network_access`, `windows_wsl_setup_acknowledged`, `features.goals`, `cli_auth_credentials_store`, MCP, навыки, сеансы и все остальные значения. В Claude Code сохраняются прочие записи `env`, `.claude.json`, плагины, MCP, настройки проектов и история. В OpenCode посторонние семантические значения сохраняются в каждом участвующем глобальном или пользовательском файле.

Корень конфигурации OpenCode по умолчанию — `%USERPROFILE%\.config`, а корень данных — `%USERPROFILE%\.local\share`. Абсолютное значение `XDG_CONFIG_HOME` или `XDG_DATA_HOME` заменяет соответствующий корень по умолчанию; пустое значение его не заменяет. Все непустые переопределения путей OpenCode (`XDG_CONFIG_HOME`, `XDG_DATA_HOME`, `OPENCODE_CONFIG` и `OPENCODE_CONFIG_DIR`) должны быть абсолютными; относительное значение блокирует сохранение снимка и переключение до записи любого файла. Глобальная конфигурация загружается из `opencode\config.json`, `opencode.json` и `opencode.jsonc` в корне конфигурации в указанном порядке; более поздние слои имеют приоритет. `OPENCODE_CONFIG` загружается последним. Приложение сохраняет итоговые `provider`, `model` и `small_model` как единый API-профиль. Данные `/connect` читаются из `opencode\auth.json` в корне данных.

OpenCode поддерживает данные `/connect` в `auth.json` и API-ключи внутри объекта `provider`; снимок включает присутствующий вариант или оба.

При применении `provider`, `model` и `small_model` удаляются из других глобальных слоёв, чтобы старый endpoint не получил приоритет. С `OPENCODE_CONFIG` цель записывается туда, а три глобальных слоя очищаются. Без переменной непустые значения канонизируются в глобальный `opencode.jsonc` и удаляются из `config.json` и `opencode.json`, даже если раньше существовал только JSON или старый файл. Снимок только с аутентификацией или пустой управляемой конфигурацией допустим: он очищает существующие значения, но не создаёт пустой `opencode.jsonc`.

Выборочное объединение сохраняет посторонние семантические значения, но не гарантирует побайтовое сохранение форматирования или комментариев при повторной сериализации JSON либо TOML.

Перед сохранением снимка или переключением OpenCode приложение в режиме только для чтения проверяет известные переменные окружения с более высоким приоритетом. Непустое значение `OPENCODE_AUTH_CONTENT` блокирует операцию. `OPENCODE_CONFIG_CONTENT` допускается только как корректный JSON/JSONC без управляемых ключей верхнего уровня `provider`, `model` и `small_model`; некорректное содержимое или любой такой ключ блокирует операцию. Если задан `OPENCODE_CONFIG_DIR`, проверяются его `opencode.json` и `opencode.jsonc`; недоступный или некорректный файл либо управляемый ключ в любом из них блокирует операцию. Встроенная или каталожная конфигурация только с посторонними ключами допускается. Приложение не изменяет эти источники, предоставленные окружением.

`CODEX_HOME` и `CLAUDE_CONFIG_DIR` меняют соответствующие корни. Проектная конфигурация OpenCode, централизованно управляемые источники и переменные окружения конкретных поставщиков остаются неуправляемыми и могут переопределить выбранный глобальный профиль после переключения; приложение не ищет и не изменяет их. Защита процессов проверяет `opencode` и `opencode-cli`. `disable_response_storage`, `features.responses_websockets_v2` и `CLAUDE_CODE_ATTRIBUTION_HEADER` остаются полями совместимости без утверждения, что они документированы во всех текущих версиях.

Codex должен использовать файловое хранилище учётных данных. Если ваша установка использует хранилище операционной системы, добавьте следующую настройку в `config.toml` активного корня Codex (по умолчанию `%USERPROFILE%\.codex`, либо `CODEX_HOME`, если переменная задана):

```toml
cli_auth_credentials_store = "file"
```

Актуальные правила хранения описаны в официальной документации по [аутентификации Codex](https://developers.openai.com/codex/auth) и [аутентификации Claude Code](https://code.claude.com/docs/en/authentication).

## Как это работает

1. Войдите через официальный процесс или настройте поддерживаемый API-сервис в обычных файлах поставщика.
2. Полностью закройте Codex, Claude Code, OpenCode и все связанные клиенты или расширения.
3. Сохраните учётную запись и управляемые API-настройки под именем `Personal`.
4. Войдите в другую учётную запись или настройте другой API-сервис и сохраните его как `Work`.
5. Выберите профиль. Если связанный процесс запущен, переключение блокируется и управляемые файлы не изменяются.
6. После подтверждения, привязанного к содержимому, текущий управляемый снимок сохраняется в последнем выбранном зашифрованном профиле, чтобы удержать обновлённые токены и намеренные API-изменения. Точный предыдущий снимок также сохраняется в отдельном DPAPI-блоке восстановления транзакции.

Приложение помечает профиль как **Последний выбранный**, а не «подтверждённый текущий». Если активный файл больше не совпадает с сохранённым снимком, переключение приостанавливается до любой записи. Подтверждайте только тогда, когда изменение является обновлением той же учётной записи. Если вы вошли в другую учётную запись вне приложения, сначала выберите **Сохранить как новый** (либо явно замените существующий профиль с правильным именем).

Кнопка **Восстановить снимок** на карточке последнего выбранного профиля проверяет совпадение активного файла с сохранённым снимком. При различии приложение предупреждает, что текущий несохранённый вход будет заменён, и привязывает разрешение к этим точным байтам. Другой активный вход не сможет повторно использовать прежнее подтверждение. Во время восстановления отдельные для транзакции и зашифрованные DPAPI данные восстановления сохраняют исходные байты до фиксации или отката операции.

Каждая составная или многофайловая транзакция сохраняет точный текущий управляемый снимок в зашифрованный блок восстановления до записи журнала, даже если он совпадает с сохранённым источником. Это обеспечивает точный откат частичной записи и безопасное обновление старого профиля только с учётными данными. После прерывания восстановление предпочитает этот снимок до переключения и синхронизирует профиль источника, если восстанавливает его. Старые журналы без блока по-прежнему возвращаются к сохранённому источнику. Если активное состояние не совпадает ни с источником, ни с целью, журнал и блок сохраняются для ручного восстановления.

Многофайловая фиксация закрыта при сбое: сначала удаляется отдельная аутентификация, затем атомарно объединяется конфигурация и последней устанавливается целевая аутентификация. Прерывание может временно оставить аутентификацию отсутствующей, но не может соединить учётные данные с endpoint другого профиля; восстановление безопасно завершает или откатывает операцию.

Старые необёрнутые профили Codex и Claude Code трактуются как учётные данные с пустой управляемой API-конфигурацией. Их активация очищает управляемые поля маршрута API и модели, чтобы не использовать сторонний endpoint предыдущего профиля. Затем настройте нужные модель/API и снова сохраните профиль. Старый профиль, являющийся активным источником, обновляется до составного формата при переключении с него.

Приложение не гарантирует постоянный вход. Отзыв на стороне поставщика, правила организации, SSO, MFA или истечение срока токена всё ещё могут потребовать обычного входа через официальный клиент.

## Настройки

Откройте **Настройки** в окне приложения, чтобы выбрать язык интерфейса или управлять запуском приложения вместе с Windows. Язык сохраняется локально для текущего пользователя Windows и может быть изменён в любое время.

Параметр **Запускать вместе с Windows** добавляет запись приложения в `HKCU\Software\Microsoft\Windows\CurrentVersion\Run`. Она действует только для текущего пользователя Windows и не требует прав администратора. Отключение удаляет только запись автозапуска, принадлежащую Coding Agent Account Switcher, и не изменяет другие запускаемые приложения.

## Модель безопасности

- Зашифрованные данные профилей хранятся в `%LOCALAPPDATA%\CodingAgentAccountSwitcher`.
- Для каждого нормализованного набора управляемых файлов используются отдельные хранилище, состояние, журнал и мьютекс. Изменение `CODEX_HOME`, `CLAUDE_CONFIG_DIR` или `OPENCODE_CONFIG` создаёт другой набор профилей.
- DPAPI `CurrentUser` не даёт другой учётной записи Windows напрямую расшифровать профиль, но не защищает от вредоносного ПО, уже работающего от имени того же пользователя.
- Кроме обычного активного файла аутентификации поставщика, расшифрованные байты снимка существуют лишь кратковременно в памяти и при атомарной замене в том же каталоге во время захвата или переключения.
- Временные и резервные файлы замены используют идентификатор транзакции восстановления. При штатном завершении оба точных файла удаляются. После прерывания механизм восстановления воссоздаёт отсутствующий активный файл из зашифрованного снимка источника или данных восстановления конкретной транзакции, удаляет все подготовительные файлы, точно принадлежащие этой транзакции, и лишь затем удаляет журнал. Зашифрованный блок восстановления удаляется только после журнала и на основе максимально возможных усилий.
- Приложение не отправляет учётные данные. Они никогда не должны попадать в журналы, задачи, отчёты о сбоях, тестовые данные или коммиты репозитория.
- Обнаружение процессов является защитной мерой без абсолютной гарантии. Не запускайте Codex, Claude Code или OpenCode до завершения операции.
- Если рабочая учётная запись управляется организацией, получите разрешение перед сохранением дополнительного зашифрованного локального снимка аутентификации.

Перед изменением кода обработки учётных данных прочитайте [SECURITY.md](SECURITY.md) и [docs/ARCHITECTURE.md](docs/ARCHITECTURE.md).

## Сборка из исходного кода

Требования:

- Windows 10 или Windows 11
- .NET SDK 8.0.400 либо более новая feature band .NET 8

```powershell
dotnet restore CodingAgentAccountSwitcher.sln
dotnet test CodingAgentAccountSwitcher.sln --configuration Release
dotnet run --project .\src\CodingAgentAccountSwitcher.App\CodingAgentAccountSwitcher.App.csproj
```

Создание автономной сборки Windows x64:

```powershell
dotnet publish .\src\CodingAgentAccountSwitcher.App\CodingAgentAccountSwitcher.App.csproj `
  --configuration Release `
  --runtime win-x64 `
  --self-contained true `
  --output .\artifacts\publish
```

## Скользящий выпуск latest

`.github/workflows/latest-release.yml` запускается при каждом push в `main`:

1. Восстанавливает зависимости и тестирует решение.
2. Публикует автономную портативную сборку Windows x64.
3. Собирает пользовательский установщик Windows x64.
4. Подготавливает портативный исполняемый файл и контрольные суммы SHA-256 для обоих исполняемых файлов.
5. Удаляет только предыдущий выпуск и тег с именем `latest`.
6. Публикует новый выпуск `latest` с установщиком, портативным исполняемым файлом и контрольными суммами для текущего коммита.

Версионные выпуски этот процесс не удаляет. Для скользящего тега `latest` параметр GitHub **immutable releases** должен быть отключён, а правила ветвей или тегов должны разрешать процессу удалять `latest`. Репозиториям, где выпуски должны быть неизменяемыми, следует использовать уникальные теги сборок.

Скользящие установщик и портативный исполняемый файл пока не подписаны, поэтому Windows SmartScreen может показать предупреждение о репутации. Перед запуском изучите исходный код и проверьте соответствующую опубликованную контрольную сумму SHA-256.
