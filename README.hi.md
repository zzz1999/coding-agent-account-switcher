# Coding Agent Account Switcher

[English](README.md) · [简体中文](README.zh-CN.md) · [繁體中文](README.zh-TW.md) · [Español](README.es.md) · [Français](README.fr.md) · [Deutsch](README.de.md) · [日本語](README.ja.md) · [한국어](README.ko.md) · [Português (Brasil)](README.pt-BR.md) · [Русский](README.ru.md) · [العربية](README.ar.md) · [हिन्दी](README.hi.md)

Codex और Claude Code के लिए एक अनौपचारिक, लोकल-फर्स्ट Windows खाता स्विचर।

Coding Agent Account Switcher, Codex और Claude Code द्वारा उपयोग की जाने वाली स्थानीय प्रमाणीकरण फ़ाइलों के नामयुक्त और एन्क्रिप्टेड स्नैपशॉट सहेजता है। यह केवल प्रमाणीकरण स्नैपशॉट बदलता है; आपकी सामान्य सेटिंग्स, MCP कॉन्फ़िगरेशन, स्किल्स, प्लगइन और प्रोजेक्ट इतिहास अपने मूल स्थानों पर बने रहते हैं।

> [!IMPORTANT]
> यह प्रोजेक्ट OpenAI या Anthropic से संबद्ध, उनके द्वारा समर्थित या प्रायोजित नहीं है। यह सदस्यता स्थानांतरित नहीं करता, साइन-इन आवश्यकताओं को बायपास नहीं करता, खाते साझा नहीं करता और प्रदाता या संगठन की नीतियों से बचने का साधन नहीं है।

“iOS 18 से प्रेरित” विवरण केवल सामान्य दृश्य दिशा को दर्शाता है। Apple इस प्रोजेक्ट से संबद्ध नहीं है और इसमें Apple के फ़ॉन्ट, प्रतीक, कलाकृतियाँ या ट्रेडमार्क शामिल नहीं हैं।

## विशेषताएँ

- iOS 18 से प्रेरित ग्लास-कार्ड डिज़ाइन वाला Windows-नेटिव WPF इंटरफ़ेस।
- अंग्रेज़ी, सरलीकृत चीनी, पारंपरिक चीनी, स्पैनिश, फ़्रेंच, जर्मन, जापानी, कोरियाई, ब्राज़ीलियाई पुर्तगाली, रूसी, अरबी और हिन्दी के अंतर्निहित इंटरफ़ेस।
- डिस्प्ले भाषा और वर्तमान उपयोगकर्ता के लिए वैकल्पिक Windows स्टार्टअप की इन-ऐप सेटिंग्स।
- Codex और Claude Code, दोनों के लिए नामयुक्त निजी और कार्य प्रोफ़ाइल।
- संबंधित एप्लिकेशन बंद होने तक स्विच को रोकने वाला प्रोसेस गार्ड।
- क्रेडेंशियल को अपारदर्शी बाइट्स की तरह संभाला जाता है: टोकन पार्सिंग, ईमेल निष्कर्षण या क्रेडेंशियल लॉगिंग नहीं होती।
- वर्तमान Windows उपयोगकर्ता के लिए Windows DPAPI से एन्क्रिप्ट किए गए प्रोफ़ाइल स्नैपशॉट।
- रोलबैक समर्थन के साथ उसी डायरेक्टरी में क्रेडेंशियल का एटॉमिक प्रतिस्थापन।
- बदला हुआ लाइव लॉगिन अंतिम चुने गए प्रोफ़ाइल स्नैपशॉट को ओवरराइट कर सके, उससे पहले स्पष्ट पुष्टि।
- अंतिम चुने गए प्रोफ़ाइल के लिए सुरक्षित **स्नैपशॉट पुनर्स्थापित करें** क्रिया, जिसमें पुष्टि बदले जाने वाले लाइव प्रमाणीकरण के सटीक बाइट्स से बंधी होती है।
- बिना एनालिटिक्स या टेलीमेट्री के केवल स्थानीय संचालन।
- `main` से स्वतः तैयार होने वाला रोलिंग Windows `latest` बिल्ड।

## समर्थित प्रमाणीकरण फ़ाइलें

| प्रदाता | बदली जाने वाली डिफ़ॉल्ट प्रमाणीकरण फ़ाइल | अपरिवर्तित रहने वाला कॉन्फ़िगरेशन |
| --- | --- | --- |
| Codex | `%USERPROFILE%\.codex\auth.json` | `%USERPROFILE%\.codex\config.toml`, स्किल्स, MCP, सेशन और अन्य स्थिति |
| Claude Code | `%USERPROFILE%\.claude\.credentials.json` | `settings.json`, `.claude.json`, प्लगइन, MCP, प्रोजेक्ट सेटिंग्स और सेशन इतिहास |

यदि `CODEX_HOME` या `CLAUDE_CONFIG_DIR` सेट है, तो एप्लिकेशन उस प्रदाता-विशिष्ट प्रमाणीकरण रूट का उपयोग करता है। फिर भी यह केवल `auth.json` या `.credentials.json` बदलता है; पास की कॉन्फ़िगरेशन फ़ाइलें अपरिवर्तित रहती हैं।

Codex को फ़ाइल-आधारित क्रेडेंशियल स्टोरेज का उपयोग करना चाहिए। यदि आपकी स्थापना ऑपरेटिंग सिस्टम क्रेडेंशियल स्टोर का उपयोग करती है, तो सक्रिय Codex रूट (डिफ़ॉल्ट रूप से `%USERPROFILE%\.codex`, या सेट होने पर `CODEX_HOME`) की `config.toml` फ़ाइल में यह सेटिंग जोड़ें:

```toml
cli_auth_credentials_store = "file"
```

वर्तमान स्टोरेज अनुबंधों के लिए आधिकारिक [Codex प्रमाणीकरण दस्तावेज़](https://developers.openai.com/codex/auth) और [Claude Code प्रमाणीकरण दस्तावेज़](https://code.claude.com/docs/en/authentication) देखें।

## यह कैसे काम करता है

1. प्रदाता के आधिकारिक लॉगिन फ़्लो से पहले खाते में साइन इन करें।
2. Codex/Claude Code तथा उससे संबंधित सभी स्थानीय क्लाइंट या एक्सटेंशन पूरी तरह बंद करें।
3. वर्तमान लॉगिन को अपनी चुनी हुई पहचान, जैसे `Personal`, के साथ सहेजें।
4. दूसरे खाते में साइन इन करें और उसे `Work` जैसे दूसरे नाम से सहेजें।
5. सहेजी गई प्रोफ़ाइल चुनें। ऐप कोई बदलाव करने से पहले संबंधित प्रोसेस जाँचता है। यदि कोई चल रहा हो तो स्विच रुक जाता है और कोई क्रेडेंशियल फ़ाइल संशोधित नहीं होती।
6. दूसरी प्रोफ़ाइल पर स्विच करते समय, बाइट-बाउंड पुष्टि के बाद वर्तमान प्रमाणीकरण फ़ाइल अंतिम चुनी गई एन्क्रिप्टेड प्रोफ़ाइल में वापस सहेजी जाती है, ताकि रीफ़्रेश हुए टोकन बने रहें।

ऐप इस प्रोफ़ाइल को “सत्यापित वर्तमान” नहीं बल्कि **अंतिम चयनित** कहता है। यदि लाइव फ़ाइल अपने सहेजे गए स्नैपशॉट से मेल नहीं खाती, तो स्विच किसी भी लेखन से पहले रुक जाता है। केवल तभी पुष्टि करें जब बदलाव उसी खाते का रीफ़्रेश हो। यदि आपने ऐप के बाहर किसी अलग खाते में साइन इन किया है, तो पहले **नए के रूप में सहेजें** चुनें (या सही नाम वाली मौजूदा प्रोफ़ाइल को स्पष्ट रूप से बदलें)।

अंतिम चयनित कार्ड का **स्नैपशॉट पुनर्स्थापित करें** बटन जाँचता है कि लाइव फ़ाइल अभी भी सहेजे गए स्नैपशॉट से मेल खाती है या नहीं। अलग होने पर ऐप चेतावनी देता है कि वर्तमान बिना-सहेजा लॉगिन बदल दिया जाएगा और अनुमति को उन्हीं सटीक बाइट्स से बाँधता है। कोई अलग लाइव लॉगिन पिछली पुष्टि का दोबारा उपयोग नहीं कर सकता। पुनर्स्थापना के दौरान केवल उस ट्रांज़ैक्शन के लिए DPAPI-एन्क्रिप्टेड रिकवरी क्रेडेंशियल, ऑपरेशन के कमिट या रोलबैक होने तक पुराने बाइट्स सुरक्षित रखता है।

ऐप स्थायी लॉगिन का वादा नहीं करता। प्रदाता द्वारा रद्द करना, संगठन नीति, SSO, MFA या टोकन की समय-सीमा समाप्त होना अभी भी आधिकारिक क्लाइंट से सामान्य साइन-इन आवश्यक बना सकता है।

## सेटिंग्स

डिस्प्ले भाषा चुनने या ऐप के Windows के साथ शुरू होने को नियंत्रित करने के लिए ऐप विंडो से **सेटिंग्स** खोलें। चुनी गई भाषा वर्तमान Windows उपयोगकर्ता के लिए स्थानीय रूप से सहेजी जाती है और कभी भी बदली जा सकती है।

**Windows के साथ शुरू करें** इस एप्लिकेशन की एक प्रविष्टि `HKCU\Software\Microsoft\Windows\CurrentVersion\Run` में जोड़ता है। यह केवल वर्तमान Windows उपयोगकर्ता पर लागू होता है और इसके लिए व्यवस्थापक अधिकारों की आवश्यकता नहीं है। विकल्प बंद करने पर केवल Coding Agent Account Switcher की अपनी स्टार्टअप प्रविष्टि हटती है; अन्य स्टार्टअप एप्लिकेशन नहीं बदलते।

## सुरक्षा मॉडल

- एन्क्रिप्टेड प्रोफ़ाइल डेटा `%LOCALAPPDATA%\CodingAgentAccountSwitcher` के अंतर्गत रखा जाता है।
- हर सामान्यीकृत प्रमाणीकरण-फ़ाइल स्थान के लिए अलग हैश-स्कोप्ड वॉल्ट, सक्रिय स्थिति, रिकवरी जर्नल और ऑपरेशन म्यूटेक्स होता है। इसलिए `CODEX_HOME` या `CLAUDE_CONFIG_DIR` बदलने पर किसी अन्य स्थान के सक्रिय खाते का दोबारा उपयोग करने के बजाय एक स्वतंत्र प्रोफ़ाइल समूह शुरू होता है।
- DPAPI `CurrentUser` किसी अन्य Windows खाते को प्रोफ़ाइल सीधे डिक्रिप्ट करने से रोकता है, लेकिन पहले से उसी Windows उपयोगकर्ता के रूप में चल रहे दुर्भावनापूर्ण सॉफ़्टवेयर से रक्षा नहीं कर सकता।
- प्रदाता की सामान्य लाइव प्रमाणीकरण फ़ाइल को छोड़कर, डिक्रिप्ट किए गए स्नैपशॉट बाइट्स कैप्चर या स्विच के दौरान केवल थोड़ी देर के लिए मेमोरी और उसी डायरेक्टरी की एटॉमिक प्रतिस्थापन प्रक्रिया में रहते हैं।
- प्रमाणीकरण प्रतिस्थापन की अस्थायी और बैकअप फ़ाइलें रिकवरी ट्रांज़ैक्शन ID का उपयोग करती हैं। सामान्य समापन दोनों सटीक फ़ाइलें हटा देता है। रुकावट के बाद रिकवरी एन्क्रिप्टेड स्रोत स्नैपशॉट या ट्रांज़ैक्शन-विशिष्ट रिकवरी क्रेडेंशियल से गुम लाइव फ़ाइल पुनर्स्थापित करती है, फिर जर्नल हटाने से पहले उसी ट्रांज़ैक्शन की सभी सटीक स्टेजिंग फ़ाइलें हटाती है।
- ऐप क्रेडेंशियल अपलोड नहीं करता। उन्हें कभी भी लॉग, इश्यू, क्रैश रिपोर्ट, परीक्षण डेटा या रिपॉज़िटरी कमिट में शामिल नहीं किया जाना चाहिए।
- प्रोसेस पहचान एक रक्षात्मक, सर्वोत्तम-प्रयास उपाय है। नया शुरू हुआ प्रोसेस स्विच के साथ टकरा सकता है, इसलिए ऑपरेशन पूरा होने तक Codex या Claude Code शुरू न करें।
- यदि कार्य खाता किसी संगठन द्वारा प्रबंधित है, तो अतिरिक्त एन्क्रिप्टेड स्थानीय प्रमाणीकरण स्नैपशॉट रखने से पहले अनुमति लें।

क्रेडेंशियल संभालने वाले कोड में बदलाव से पहले [SECURITY.md](SECURITY.md) और [docs/ARCHITECTURE.md](docs/ARCHITECTURE.md) पढ़ें।

## स्रोत से बिल्ड करें

आवश्यकताएँ:

- Windows 10 या Windows 11
- .NET SDK 8.0.400 या कोई नया .NET 8 feature band

```powershell
dotnet restore CodingAgentAccountSwitcher.sln
dotnet test CodingAgentAccountSwitcher.sln --configuration Release
dotnet run --project .\src\CodingAgentAccountSwitcher.App\CodingAgentAccountSwitcher.App.csproj
```

स्व-निहित Windows x64 बिल्ड बनाएँ:

```powershell
dotnet publish .\src\CodingAgentAccountSwitcher.App\CodingAgentAccountSwitcher.App.csproj `
  --configuration Release `
  --runtime win-x64 `
  --self-contained true `
  --output .\artifacts\publish
```

## रोलिंग latest रिलीज़

`main` पर हर push के लिए `.github/workflows/latest-release.yml` चलता है:

1. समाधान को रीस्टोर और टेस्ट करता है।
2. स्व-निहित Windows x64 बिल्ड प्रकाशित करता है।
3. ZIP संग्रह और SHA-256 चेकसम बनाता है।
4. केवल पिछली `latest` नामक रिलीज़ और टैग हटाता है।
5. वर्तमान कमिट के लिए नई `latest` रिलीज़ बनाता है।

यह वर्कफ़्लो संस्करणयुक्त रिलीज़ कभी नहीं हटाता। रोलिंग `latest` टैग के लिए GitHub का **immutable releases** विकल्प अक्षम रहना चाहिए, और ब्रांच या टैग नियमों को वर्कफ़्लो द्वारा `latest` हटाने की अनुमति देनी चाहिए। अपरिवर्तनीय रिलीज़ की आवश्यकता वाले रिपॉज़िटरी को अलग-अलग बिल्ड टैग इस्तेमाल करने चाहिए।

रोलिंग एक्ज़ीक्यूटेबल अभी हस्ताक्षरित नहीं है, इसलिए Windows SmartScreen प्रतिष्ठा चेतावनी दिखा सकता है। इसे चलाने से पहले स्रोत की समीक्षा करें और प्रकाशित SHA-256 चेकसम सत्यापित करें।
